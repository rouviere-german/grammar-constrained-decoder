# Model card: kn5-json-lm

Format after Mitchell et al., "Model Cards for Model Reporting" (FAT* 2019). Numbers are copied
from real runs, with the command that produced them.

## Model details

- **Name:** `kn5-json-lm`, registered under the alias `production` in the content-addressed
  registry (`ml/registry.py`); the version digest is printed by
  `uv run grammar-constrained-decoder train`.
- **Type:** interpolated modified Kneser-Ney 5-gram language model over token ids (Kneser and Ney
  1995; Chen and Goodman 1998), implemented in numpy (`lm/kneser_ney.py`), with a byte-level BPE
  tokenizer of 1,024 tokens trained with Hugging Face `tokenizers` (`lm/tokenizer.py`). The three
  discounts per order are Chen and Goodman's count-of-counts estimates, clamped to
  `[0.1, k]`; the floor keeps every next-token distribution strictly positive on sparse data
  (`tests/unit/test_lm.py::test_sparse_count_statistics_never_zero_a_probability`). The shipped
  model's estimates are all between 0.54 and 2.46, so the floor does not change it.
- **Owner:** Rouviere German. **License:** MIT (code and synthetic data).
- **Artifacts:** `counts.npz` (npz, loaded with `allow_pickle=False`), `tokenizer.json` (the
  library's JSON), `model.json`; never pickle.
- **Run manifest:** `manifest.json` next to the registry: seed, SHA-256 of the training and
  held-out corpora, tokenizer, vocabulary and counts, package versions, parameters and metrics.
  Loading refuses any file whose hash differs from the manifest.

## Intended use

- **Primary use:** a small, fully offline, deterministic next-token distribution for developing,
  testing and benchmarking grammar-constrained decoding: token masks, exactness, overhead and
  distortion.
- **Out of scope:** any use where the *content* of generated JSON matters. The model has no
  knowledge, no instruction following and a four-token memory.

## Training data

- **Source:** synthetic, generated by `training/corpus.py` with seed 0: 120 prompted JSON documents
  for each of 18 train schemas (2,160) plus 600 template sentences. Prompts are
  `"Q: <description>\n<schema id>:\n"` followed by the canonical JSON of a sampled instance.
  Values come from small built-in word lists (fictional names built from famous computer
  scientists' first and last names, European cities, generic words) or from random walks over the
  string's pattern automaton. No real personal data.
- **Held-out:** 12 schemas (20 documents each) are never seen in training.
- **Contract:** `ml/contracts.py` checks every record: JSON parses, validates against its schema
  with `jsonschema`, equals its canonical serialization, uses only train-split schemas, and the
  train and eval schema sets share no id or content hash. Failures report check names and counts,
  never values.

## Evaluation

Measured with `uv run grammar-constrained-decoder train --workdir var/model` on the machine listed
in the README Results section (Windows 10, Python 3.12.14, 6 logical CPUs):

| Metric | Value | Note |
|---|---:|---|
| training tokens | 136,239 | corpus of 2,760 documents, 1,024-token vocabulary |
| training time | 2.8 s | corpus 1.4 s, tokenizer 0.08 s, counts 0.38 s, evaluation 0.6 s |
| train perplexity (200 sampled training documents) | 2.04 | the model memorizes seen patterns |
| held-out perplexity (240 documents, 12 unseen schemas) | 446.3 | unseen field names and prompts |

The corpus, tokenizer and counts hashes are identical across runs with the same seed; the model
version digest also covers the run manifest (run id, creation time, dataset paths), so it differs
between runs.

Downstream behavior (from `bench/bench_validity.py` and `bench/bench_distortion.py`, see README
Results): unconstrained sampling produced 0 valid documents out of 1,000 on held-out schemas and
0 out of 360 on the training schemas, because after four tokens the model no longer knows which
schema it is writing and mixes fields from different schemas. Masked decoding with the compiled
grammar produced 1,000 valid documents out of 1,000. For comparison, the bench also fits a 5-gram
on 120 documents of each held-out schema alone (same tokenizer and code, not the shipped model):
it is valid in 5.8% of unconstrained samples, 17.9% with three retries, and 100%
constrained, because high-entropy values (random identifiers, numbers) still push a four-token
context off the document structure.

## Robustness, drift and monitoring

- **Robustness:** decoding under a deliberately adversarial model (all mass on breaking tokens)
  still yields valid output (`tests/unit/test_decoder.py::test_constrained_outputs_are_always_valid`).
  Literal `<|eos|>` in prompts cannot end a document (`tests/unit/test_lm.py::test_literal_eos_markers_in_text_are_not_special`).
- **Drift:** the service computes PSI between recent prompt token lengths (rolling window of 500)
  and the training prompt lengths stored with the model, exported as `app_prompt_length_psi`
  (`ml/drift.py`; common reading: above 0.2 is a shift).
- **Integrity:** registry and manifest hash verification at load; `/readyz` fails if the model
  does not load.
- **Retraining trigger:** a new bundled schema or a sustained PSI above 0.2. Retraining is a
  deterministic, seconds-long rebuild; the corpus, tokenizer and counts hashes must match across
  identical runs (`tests/integration/test_pipeline.py::test_training_is_reproducible`).

## Ethical considerations

- **Validity is not safety.** Constrained decoding makes output parse and validate; it does not
  make it true, appropriate or authorized. Downstream systems must treat outputs as untrusted.
- The corpus is synthetic; names are recombined from a fixed list of public figures' first and last
  names and never refer to real individuals' data.
- Prompts and outputs are not logged by the service.

## Caveats and recommendations

- Constrained greedy output is often semantically odd (a timestamp-looking string in a name field):
  the mask chooses among valid continuations the ones the weak model likes, not sensible ones.
- Masked sampling is distorted relative to the model conditioned on validity; the distortion
  study quantifies it on 20 tiny schemas. Do not interpret masked-sampling frequencies as the
  model's beliefs about valid outputs.
- The decoder accepts any model with a `logprobs(context)` method; results here say nothing about
  neural models.
